            yoystar大约 20 分钟注解Spring框架查询
            # Spring中的注解：
            Spring常用注解
            • @Component 通用声明使用Spring管理Bean
            • @Controller 表现层声明
            • @Service 业务层声明(一般写在Impl实现类上)
            • @Repository Dao持久层声明
            • @Mapper Springboot Mybatis中的注解，给Dao接口添加，扫描这个接口，启动创建dao的代理类
            • @Autowired 按类型自动装配生成Bean注入引用类型(配合@Qualifier注解按照名称生成bean) ，依赖注入时先按照byType类型，如果有多个bean，再按照byName名称(来自spring定义)
            • @Resource 依赖注入时先按照byName类型，如果找不到bean，再按照byType名称(来自java规范定义)
            • @Value(${xxxx}) 注入简单类型 ，读取属性
            • @Conditional注解 给类或者方法添加一个判断条件 判断bean是否能被装载到ioc容器(用于bean加载控制)
            • @PostConstruct注解，修饰类中的某个方法(生命周期回调方法)，定义Bean构造方法后初始化方法注解，当这个类被当做bean创建时，运行被此注解修饰的方法，相当于init-method初始化方法(对应destroy @PreDestory)
            • @PreDestroy 定义Bean销毁前方法注解
            • @Aspect AOP声明(识别@PointCut和@Before等)
            • @TableName("rb1_xxx")设置当前模型类对应的数据库表关系
            • @TableField(value="xxx") 实现模型类属性名和数据库表的列名之间的映射关系，防止字段不一样导致查询异常。
            • @TableField(exist=false) 设置在模型类的字段上，区分是否在数据库表中存在，设为false不存在时，生成sql查询时就不会查询这个字段。一般运用于不在数据库中保存的字段，例如登录状态isOnLine等。
            • @TableField(value="xxx",select=false)设置属性是否参与查询，可以防止password类型的数据泄露等
            • @TableId(type=IdType.AUTO)注解，用于主键属性上，设置当前类主键属性生成策略。(也可以在yml中配置全局id生成策略：mybatis-plus.xxx...xxx.id-type: assgin_id 配置)
            • AUTO:自动递增生成主键id
            • NONE: 不设置id生成策略
            • INPUT:用户手工输入id
            • ASSIGN_ID:雪花算法生成id(可兼容数值型与字符串型) 数据库使用big int(20存储)
            • ASSIGN_UUID:以UUID生成算法作为id生成策略
            • @TableLogic(value="0"，delvalue="1")注解，表示该属性是逻辑删除标志字段，默认值是0，代表未被删除，数值1代表被逻辑删除。使用该注解，mp自动将delete改成update
            • @Version注解配置乐观锁
            • @CnofigurationProperties注解(支持松散绑定) ，可以为第三方bean注入属性 ，例如@CnofigurationProperties(perfix="datasourse")给druid注入属性
            • @DurationUnit(ChronoUnit.MINUTE)注解，给private Duration serverTimeOut;指定时间范围单位
            • @DataSizeUnit(DataUnit.MEGABYTES)注解，给private DataSize dataSize;指定存储空间单位
            • @validated注解，开启Bean数据校验，JSR303校验规范的校验注解，在类中进行校验，例如@Max @Min注解等。（备注：需要引入2个坐标：validation-api和hibernate-validator）
            # SpringConfig中的注解：
            SpringConfig配置注解
            • @Configuration 声明当前类为配置类(配合@Bean注解)
            • @Bean注解 表示当前方法的返回值是一个Bean(用于管理第三方Bean)
            • @PropertySource 在SpringConfig中设置加载properities文件中的属性值
            • @ComponentScan 配置Bean扫描路径
            • @Import 在SpringConfig中精准导入配置文件(其他配置文件无需写@Configuration 声明)
            • @EnableAspectJautoProxy 在SpringConfig中 告诉Spring有用注解开发的AOP(启动通知类中的@Aspect)
            • @EnableTransactionManagerment 在SpringConfig配置 表示开启事务管理 用注解式事务驱动
            • @EnableAdminServer注解 开启SpringAdmin端点监控功能(服务端)
            • 导入服务端坐标spring-boot-admin-starter-server 版本号跟springboot版本号一致(客户端需要导入spring-boot-admin-starter-client)
            • yml配置中设置端口
            • 启动程序中 打开@EnableAdminServer注解
            # SpringMVC注解：
            SpringMVC注解
            • @EnableWebMvc 打开mvc 多项辅助功能 包括开启json转换对象功能
            • @Controller 声明成bean
            • @RestController 声明成bean,设置当前控制器类为RESTful风格， 等同于正给类上添加@Controller + @ResponseBody两个注解组合功能
            • @RequestMapping("/xxx/xxx")访问路径
            • @ResponseBody 返回json数据 设置当前控制器方法响应内容为当前返回值(返回的东西作为整体内容给前端 无需解析)设置当前控制器返回值作为“响应体”（写在类上，该类的所有方法都有该注解功能 ）可被@RestController代替
            • @RequestParam ("xxx") 形参注解 request 传递参数注解 用于接收url地址传参或表单传参 （获取参数方法1）
            • @RequestBody 形参注解 将请求中请求体所包含的数据传递给请求参数（此注解一个处理器方法只能使用一次）将外部传递的json数组数据映射到形参的集合对象中作为数据 用于接收json数据 （获取参数方法2）
            • @PathVariable 形参注解 REST风格中，表示从路径取值，并赋值给形参 用于接收路径参数，使用{参数名称}描述路径参数 （获取参数方法3）
            • @DateTimeFormat 形参注解 设定日期时间型数据格式 例如：@DateTimeFormat(pattern="yyyy/MM/dd HH:mm:ss")
            # lombok工具及注解：
            lombok工具及注解

            自动生成构造方法(有参@AllArgsConstructor和无参@NoArgsConstructor) 自动生成get/set/toString方法等

            注解↓

            • @Setter:为模型类的属性提供setter方法
            • @Getter:为模型类的属性提供getter方法
            • @ToString:为模型类的属性提供toString方法
            • @EqualsAndHashCode:为模型类的属性提供equals和hashcode方法
            • @RequiredArgsConstructor: 会生成一个构造函数，该构造函数接收所有 final 和 @NonNull 字段作为参数，但并不会为所有字段生成一个构造函数，也不会生成一个无参数的构造函数（可用于定义成final类型的对象，以构造函数的方式依赖注入）
            • @Data:是个组合注解，包含上面的注解的功能
            • @NoArgsConstructor:提供一个无参构造函数
            • @AllArgsConstructor:提供一个包含所有参数的构造函数
            • @Slf4j 注解 ，直接使用log.xxx即可。相当于：private static final Logger log = LoggerFactory.getLogger(BookController.class); 类中可以直接使用Log ，由lombok提供。
            # Aspect切入点表达式：
            Aspect切入点表达式及注解
            • @Pointcut("execution (void com.hmct.xxx.xxxx())")切入点
            • @Before 切入点之前
            • @After 切入点之后(就算原始对象抛出异常 也会运行)
            • @AfterReturning 正常运行完(没有抛异常)返回值之后
            • @AfterThrowing 原始对象抛出异常之后运行
            • @Around 环绕切入点 配合(ProceedingJoinPoint pjp)参数 pjp.proceed()代表原始操作的执行位置(不操作会起到对原始操作隔离的效果 可以用于权限鉴定)(pjp.getSignature获取原始方法的执行签名信息 包括类名方法名等)。同时需要注意返回值需要是返回Object。
            • @Pointcut("execution (* com.hmct.*.*Service.find*(..))")将项目中所有的业务层接口方法中以find开头的方法匹配 添加增强功能(使用通配符描述AOP切入点表达式)
            • @Pointcut("execution (* com.hmct.*.*Service.save*(..))")将项目中所有的业务层接口方法中以save开头的方法匹配 添加增强功能(使用通配符描述AOP切入点表达式)
            • *切入点通配符：单个独立的任意符号(1个 不可以是0个)
            • ..切入点通配符：多个连续的任意符号(0个 1个 多个)
            • +切入点通配符：专用于匹配子类类型
            • @AfterReturning(pointcut = "@annotation(Log)", returning = "jsonResult")代表切入点是@Log的注解位置
            # REST风格：(开发的过程中，大多遵从REST风格来访问后台服务 )
            RestFul风格及注解

            请求的方式比较多，但是比较常用的就4种，分别是 GET , POST , PUT , DELETE 。

            描述模块的名称通常使用复数，也就是加s的格式描述，表示此类资源，而非单个资源，例 如:users、books、accounts 等

            • 发送GET请求是用来做查询 @GetMapping
            • 发送POST请求是用来做新增/保存@PostMapping
            • 发送PUT请求是用来做修改/更新@PutMapping
            • 发送DELETE请求是用来做删除 @DeleteMapping(“/{id}”)

            例如:@RequestMapping(value = "/users/{id}/{name}",method = RequestMethod.POST|GET|PUT|DELETE )

            @PathVariable(“id”) @PathVariable(“name”) 形参注解 表示从路径取值，并赋值给形参

            接收参数的三个注解：

            • @PathVariable 用于接收RESTFul风格路径参数
            • @RequestParam 用于接收url地址传参 或者 表单传参
            • @RequestBody 用于接收json数据请求体

            Spring异常处理器及注解
            • @ControllerAdvice统一异常处理注解
            • @RestControllerAdvice Rest风格统一异常处理的类注解,用于标识当前类是REST风格对应的异常处理器
            • @ExceptionHandler(xxxxxxException.class) 异常处理标志注解，出现异常后终止原始控制器执行,并转入当前方法执行。

            创建异常分类以及处理方法（继承RuntimeException或者Exception）：

            • 业务异常BusinessException

            发送提醒消息给用户 规范操作

            • 系统异常 SystemException

            发送消息安抚-给运维人员发消息-记录日志

            • 其他异常 Exception

            发送消息安抚-给开发人员发消息-记录日志

            在Service中 try catch，将其他类型Exception，通过throw new XXXexception转换成统一异常处理的异常

            (sentinel统一异常处理需要实现BlockExceptionHandler接口并重写handle方法，同时声明成bean,通过e.getRule()获取资源和规则的详细信息)

            # 开启事务管理器(3步)：
            开启事务及注解
            • @EnableTransactionManagerment注解，在SpringConfig配置 表示开启事务管理 用注解式事务驱动
            • 配置平台事务管理器PlarformTransactionManager，通过形参传入DataSource,返回DataSourceTransactionManager(放在JdbcConfig配置类中即可)
            • @Transactional注解，Service业务层接口上添加(这个service所有接口都添加了事务管理 impl实现类中无需再添加)
