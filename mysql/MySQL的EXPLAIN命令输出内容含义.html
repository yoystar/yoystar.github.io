    MySQL的EXPLAIN命令输出内容含义

    yoystar大约 4 分钟MySQLEXPLAINSQL调优

    EXPLAIN 命令用于分析 SQL 查询的执行计划，帮助了解数据库引擎如何执行查询。

    直接在select语句之前加上关键字 explain或者desc 例如：explain select 字段列表 from 表名 where 条件 ，根据结果重点分析type 和 filter(百分比 数大越好)以及Extra等字段，来分析性能。

    explain的type性能由高到低：NULL(不访问表)→system(访问系统表)→const(根据主键和唯一索引访问 是正常业务优化目标)→eq_ref→ref(非唯一性索引访问)→range→index(用了索引 但是遍历整个索引树)→all(全表扫描)

    explain的extra性能高低：using where,using index（覆盖索引情况，使用了索引获得了所有查询列数据，且不需要回表查询） 大于> using index condition（使用了索引，但是需要回表查询数据）

    以下是 EXPLAIN 输出中各列的详细含义：

    1. id 含义：查询的标识符，表示查询中操作的顺序 说明： 相同的 id 表示同一组操作 数字越大越先执行 NULL 表示结果集的联合操作
    2. select_type 含义：查询的类型 常见值： SIMPLE：简单查询，不包含子查询或 UNION PRIMARY：最外层查询 SUBQUERY：子查询 DERIVED：派生表（FROM 子句中的子查询） UNION：UNION 中第二个或后面的查询 UNION RESULT：UNION 的结果
    3. table 含义：查询涉及的表名 说明： 可能显示表的别名 表示派生表，N 是对应的 id
    4. partitions 含义：查询将从哪些分区获取数据 说明： 仅当表进行了分区时才有意义 NULL 表示表未分区或无法确定使用的分区
    5. type 含义：访问类型，表示数据库引擎查找数据的方式 常见值（性能从最好到最差 常用标红）： null：不访问表 system：表只有一行数据 const：通过主键或唯一索引查找，最多返回一条记录(根据主键和唯一索引访问，是正常业务优化目标) eq_ref：使用主键或唯一索引进行连接 ref：使用非唯一索引进行查找 fulltext：使用全文索引 ref_or_null：类似 ref，但会额外搜索 NULL 值 index_merge：使用索引合并优化 unique_subquery：IN 子查询使用唯一索引 index_subquery：类似 unique_subquery，但使用非唯一索引 range：使用索引进行范围查询 index：全索引扫描，用了索引，但是遍历整个索引树，比全表扫描好 ALL：全表扫描，性能最差
    6. possible_keys 含义：可能使用的索引列表 说明： 显示查询可能使用的所有索引 NULL 表示没有可用的索引
    7. key 含义：实际使用的索引 说明： 显示优化器最终选择的索引 NULL 表示未使用索引
    8. key_len 含义：使用的索引长度（字节） 说明： 表示索引中使用的字节数 较短的长度意味着索引使用更高效 可以判断复合索引中使用了多少列
    9. ref 含义：索引比较的列或常量 说明： 显示哪些列或常量用于查找索引中的值 const 表示常量值 表名.列名 表示连接查询
    10. rows 含义：预计需要检查的行数 说明： 这是一个估计值，不是精确值 数值越小表示查询效率越高
    11. filtered 含义：按表条件过滤的行百分比 说明： 表示满足查询条件的行数百分比 值越高越好，100 表示没有行被过滤
    12. Extra 含义：附加信息 常见值：（性能从高到低） No tables used：查询没有使用表

    Select tables optimized away：通过索引直接获取结果，无需访问表，常见于MIN/MAX+索引

    Using index：使用覆盖索引，索引获得了所有查询列数据，且不需要回表

    Using index condition：索引条件下推，会先使用索引过滤部分数据，然后再回表获取其他列

    Using where：使用WHERE子句过滤结果，但不是所有条件都能用索引处理

    Using join buffer：使用连接缓冲区来执行连接操作

    Using filesort：需要额外的排序操作，无法使用索引排序

    Using temporary：使用临时表，需要创建临时表来处理查询，通常出现在分组GROUP BY或排序ORDER BY操作

    Impossible WHERE：WHERE条件永远为false，查询不会返回任何行，特殊情况（查询不会返回任何结果）
